Issue 1 – SIP dialog termination is not propagated to the AI bridge

Symptoms

When the caller hangs up:

Yeastar correctly terminates the SIP call.
Phone disconnects.
PSTN disconnects.
AIO Voice Connect continues streaming audio to ElevenLabs.
The AI continues speaking even though the SIP dialog no longer exists.

⸻

Expected flow Remote Phone │ ▼ BYE │ ▼ AIO Voice Connect │ ▼ Terminate SIP Dialog │ ▼ Stop RTP │ ▼ Close ElevenLabs WebSocket │ ▼ Destroy Bridge

Actual behavior Remote Phone │ ▼ BYE │ ▼ SIP dialog removed

Bridge still running

RTP still running

WebSocket still open

ElevenLabs continues talking

Diagnostic

The SIP dialog teardown is not notifying the bridge manager.

This affects both inbound and outbound.

That strongly indicates the problem is inside the shared bridge lifecycle rather than the inbound or outbound call logic.

Overall Diagnosis

The signaling and media setup appear healthy: registration, authentication, call establishment, RTP negotiation, and ElevenLabs connectivity all work correctly in both inbound and outbound modes.

The failures are concentrated in call teardown, specifically when the SIP endpoint (phone/PSTN side) ends the call.

Primary issue

The SIP BYE/dialog termination event is not fully propagated to the shared bridge manager, leaving the RTP bridge and ElevenLabs WebSocket active after the SIP call has ended.

Secondary issue

When the AI ends a conversation, bridge cleanup occurs before all queued RTP audio has been transmitted, causing the last sentence to be clipped occasionally.
