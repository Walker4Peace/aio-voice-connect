We want to improve SIP Agent by adding generic outbound calling and AI function/tool calling.

1. Generic Outbound Calling

The outbound feature must be generic and not tied to any specific business (no e-commerce, CRM, etc.).

The goal is that any external application can trigger a call through an HTTP API.

Example flow:

1. An external application sends an HTTP request to SIP Agent.
2. SIP Agent places the SIP call through Yeastar.
3. When the callee answers, the AI starts the conversation using the configured provider (currently ElevenLabs).
4. After the call ends, the API returns or stores the result.

The API should accept runtime data such as:

* phone number
* optional caller ID
* optional variables/context
* optional first message override
* optional system prompt override
* optional metadata
* optional webhook URL for the result

Do not require editing the agent configuration or restarting the service for every outbound call.

The outbound request should simply use the existing agent and inject the runtime context.

⸻

2. Shared Agent Configuration

Do not create separate inbound and outbound agents.

One SIP Agent configuration should work for both:

* inbound calls
* outbound calls

The only difference should be how the conversation is started.

Everything else should remain the same:

* AI provider
* prompt
* voice
* model
* SIP account
* provider settings

Only the runtime call data should change.

⸻

3. AI Functions / Tools

Add support for AI function/tool calling similar to what SIP4AI supports.

A SIP Agent should be able to define multiple tools/functions that the AI can call during the conversation.

Examples:

* HTTP Request
* Webhook
* Transfer Call
* Hang Up
* Send DTMF
* Custom JavaScript
* Future integrations

Each tool should define:

* name
* description
* parameters/schema
* execution type
* timeout
* optional confirmation before execution

When the AI requests a tool, SIP Agent executes it and returns the result back to the AI so the conversation can continue naturally.

The implementation should be provider-independent so it can work with ElevenLabs now and OpenAI, Gemini, or future providers later.

⸻

Please review the current architecture first and implement these features in a clean, extensible way without breaking the existing inbound functionality.
