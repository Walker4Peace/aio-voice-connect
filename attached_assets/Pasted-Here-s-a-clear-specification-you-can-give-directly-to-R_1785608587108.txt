Here’s a clear specification you can give directly to Replit.

⸻

Add ElevenLabs Post-Call Webhook Support to AIO Voice Connect

Goal

I want AIO Voice Connect to receive the final structured results of an AI phone call from ElevenLabs after the conversation ends.

The platform itself does not perform any AI analysis. It simply:

* Starts outbound calls.
* Connects Yeastar ↔ AI Provider.
* Receives the final structured results from the AI provider.
* Stores them in the database.
* Makes them available through the API (and later webhooks to CRM/ERP).

⸻

Current Flow

CRM / ERP
      │
      │ POST /api/outbound/call
      ▼
AIO Voice Connect
      │
      ▼
Yeastar SIP
      │
      ▼
ElevenLabs AI Agent

Currently the call finishes with:

{
  "status": "completed",
  "result": null
}

Instead I want:

{
  "status": "completed",
  "result": {
    "caller_name": "Yassine",
    "delivery_address": "Boulevard Maghreb Arabi N°8",
    "additional_notes": "Deliver after 5 PM",
    "order_confirmed": true,
    "evaluation": {
      "caller_identified": true,
      "goal_achieved": true,
      "information_precise": true
    }
  }
}

⸻

ElevenLabs Configuration

Inside ElevenLabs I configured:

Data Collection

* caller_name (String)
* delivery_address (String)
* additional_notes (String)
* order_confirmed (Boolean)

Evaluation Criteria

* Caller Identified
* Goal Achieved
* Information Precise

ElevenLabs also supports a Post-Call Webhook.

I want to use that webhook.

⸻

Required Backend Changes

1. Create a public webhook endpoint

Example:

POST /api/providers/elevenlabs/post-call

This endpoint will receive the POST request from ElevenLabs after every completed conversation.

⸻

2. Verify the webhook

ElevenLabs signs requests using HMAC.

Verify the ElevenLabs-Signature header before processing.

⸻

3. Match the webhook to an outbound call

When starting a conversation with ElevenLabs, include metadata such as:

{
    "outboundCallId": 25
}

or another identifier that is returned in the webhook.

When the webhook arrives, use this identifier to find the corresponding outbound_call record.

⸻

4. Store the result

Update the outbound call:

{
    "status": "completed",
    "result": {
        ...
    }
}

The result field should contain the complete payload returned by ElevenLabs (or at least the useful structured fields).

Do not create database columns for every possible value.

Keep result as a JSON object because different AI agents will return different information.

⸻

5. Update GET endpoint

When calling

GET /api/outbound/calls/:id

Return:

{
    "id":25,
    "status":"completed",
    "result":{
        "caller_name":"Yassine",
        "delivery_address":"Boulevard Maghreb Arabi N°8",
        "additional_notes":"Deliver after 5 PM",
        "order_confirmed":true,
        "evaluation":{
            "caller_identified":true,
            "goal_achieved":true,
            "information_precise":true
        }
    }
}

⸻

Future CRM Integration

Later, external applications (CRM / ERP / n8n) will:

POST /api/outbound/call

Wait until the call finishes.

Then either:

GET /api/outbound/calls/:id

or receive a webhook from AIO Voice Connect.

The CRM should never communicate directly with ElevenLabs.

AIO Voice Connect is the single integration point.

⸻

Design Requirements

* Provider-agnostic architecture.
* Today: ElevenLabs.
* Future: OpenAI Realtime, Gemini Live, Deepgram, etc.

AIO Voice Connect should never contain provider-specific business logic.

It should simply:

1. Receive structured results from the AI provider.
2. Normalize/store them.
3. Expose them through the API.

⸻

Important

Please first verify the exact payload sent by the ElevenLabs Post-Call Webhook (field names, metadata support, data collection fields, evaluation fields, conversation ID, etc.) and implement the endpoint according to the official ElevenLabs webhook specification rather than making assumptions. This will ensure the integration is fully compatible with the official API.
